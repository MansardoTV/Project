# ПОЯСНИТЕЛЬНАЯ ЗАПИСКА
## Дисциплина: Системы искусственного интеллекта (СиВММиГО)
**Тема: Разработка интеллектуальной поисковой системы для корпоративного мессенджера на базе RAG-архитектуры**

---

### Введение

**Задача и актуальность:**
В современной корпоративной среде объем передаваемой информации в мессенджерах растет экспоненциально. В VK Workspace более 20% пользователей ежедневно используют поиск. Актуальность задачи заключается в том, что стандартный полнотекстовый поиск (по ключевым словам) часто не находит релевантные сообщения, если запрос сформулирован синонимами или содержит смысловые неточности. Требуется система, понимающая семантику вопроса.

**Применимость ML/DL технологий:**
Традиционные алгоритмы поиска (вроде TF-IDF) ограничены лексическим совпадением. Технологии глубокого обучения (Deep Learning), в частности векторные эмбеддинги и трансформеры, позволяют преобразовывать текст в многомерные векторы, где близкие по смыслу фразы находятся рядом. Это делает возможным «смысловой» поиск (Semantic Search).

**Современное состояние области:**
В области Retrieval-Augmented Generation (RAG) и информационного поиска сейчас доминируют двухстадийные подходы: извлечение кандидатов (Retriever) и их переранжирование (Reranker).
*   *Источники:* Модели семейства BGE (Beijing Academy of Artificial Intelligence), Qwen-Embedding и архитектуры Cross-Encoders (например, на базе BERT/RoBERTa), которые показывают SOTA-результаты в задачах ранжирования.

---

### Основная часть

#### 1. Описание данных и постановка задачи

**Предметная область и источник данных:**
Данные представляют собой экспорт переписок из корпоративного мессенджера VK Workspace. Датасет имитирует реальную работу ИТ-команд (обсуждение разработки на Go, релизов, митапов).

**Объем и состав:**
*   **Формат:** JSON-структуры.
*   **Сообщения:** Массив объектов с полями `id`, `text`, `time`, `sender_id`, `parts` (вложения), `mentions`.
*   **Вопросы (Ground-truth):** Набор из 20+ эталонных вопросов, каждый из которых содержит:
    *   `text` — оригинальный запрос;
    *   `hyde` — гипотетический ответ для расширения поиска;
    *   `entities` — извлеченные сущности (даты, люди, документы).

**Тип задачи:**
Задача **информационного поиска и ранжирования (Information Retrieval & Ranking)**. Цель — среди тысяч сообщений (чанков) отобрать топ-50 и отсортировать их по убыванию вероятности релевантности эталонному ответу.

#### 2. Разведочный анализ и подготовка данных

**Анализ качества и характеристик:**
*   **Длины сообщений:** Распределение крайне неравномерное. Есть как «мусорные» сообщения (эмодзи, «ок»), так и объемные логи/код.
*   **Контекст:** Анализ baseline-решения показал, что точность Recall@50 на «сыром» тексте составляет всего ~0.46. Короткие сообщения без контекста (кто писал и когда) практически не находятся.

**Подготовка данных:**
*   **Очистка:** Исключение системных событий, не несущих смысловой нагрузки.
*   **Нормализация:** Приведение текстовых полей к единому регистру для разреженного поиска (BM25).

#### 3. Отбор признаков и проектирование пайплайна

**3.1. Проектирование признаков (Feature Engineering):**
Вместо простых текстовых полей были созданы **синтетические метаданные (Semantic Anchors)** через функцию `render_v20`. В текст каждого сообщения внедряются префиксы:
*   `chat:` — для привязки к тематике канала.
*   `author:` — позволяет искать сообщения конкретных сотрудников.
*   `date:` — критически важен для обработки временных сущностей.
*   `file:` — позволяет искать сообщения по названиям прикрепленных документов.

**3.2. Архитектура пайплайна обработки:**
Итоговая цепочка обработки данных:
1.  **Ingestion:** Чтение JSON -> объединение сообщений в единый поток.
2.  **Chunking:** Разбиение на фрагменты (512 символов) с наложением (128 символов) для сохранения контекста между сообщениями.
3.  **Vectorization:** Параллельное получение плотных векторов (через внешний API) и разреженных векторов (локальный BM25).
4.  **Retrieval (V23 Super-Ensemble):** Гибридный поиск по 4 каналам (Query Dense, HyDE Dense, Sparse Main, Sparse Opt).
5.  **Fusion:** Объединение результатов методом Reciprocal Rank Fusion (RRF).
6.  **Reranking:** Переранжирование топ-35 кандидатов кросс-энкодером `Llama-Nemotron-Reranker-1B`.
7.  **Post-processing:** Heuristic Boosting по датам и авторам.

#### 4. Выбор модели и настройка гиперпараметров

**4.1. Разбиение данных:**
Для валидации использовался «Golden Set» из 20 вопросов, предоставленный организаторами. В качестве тренировочных данных для настройки весов бустинга использовался пример чата `Go Nova.json`.

**4.2. Рассмотренные модели и алгоритмы:**
1.  **Baseline (Dense + Sparse):** Одностадийный поиск по тексту. Плюс — скорость, минус — низкая точность на сложных запросах.
2.  **Super-Ensemble V23 (Final):** Многостадийный поиск с Reranker. Плюс — высочайшая точность, минус — потребление ресурсов (SLA достигает 50с).

**4.3. Настройка гиперпараметров:**
*   **Chunk Size (512):** Оптимален для покрытия 2-3 коротких сообщений.
*   **Rerank Limit (35):** Максимальное число кандидатов, которое успевает обработать кросс-энкодер в рамках лимита в 60 секунд.
*   **DENSE_LIMIT (150):** Расширенный префетч для захвата семантически близких, но лексически разных сообщений.

**4.4. Сравнение моделей:**

| Подход | Recall @50 | nDCG @50 | VK Score |
| :--- | :---: | :---: | :---: |
| Baseline (Baseline Solution) | 0.5120 | 0.3800 | 0.4600 |
| **V23 (Super-Ensemble + Reranker)** | **0.6232** | **0.5173** | **0.6020** |

### Заключение

**Результат:** Решена задача построения интеллектуального поиска с итоговым баллом **0.6020**.
**Практический смысл:** Система позволяет сотрудникам мгновенно находить решения задач в истории чатов, даже если они не помнят точных формулировок, используя естественный язык.
**Почему это работает:** 
1.  **Гибридность:** BM25 находит точные термины, а Dense-векторы — смысл. 
2.  **Метаданные:** Внедрение автора и даты в текст чанка «подсказало» модели скрытые связи. 
3.  **Reranker:** Кросс-энкодер исправил ошибки первичного поиска, поставив наиболее точные ответы на первые места (что подтверждается ростом nDCG).
**Выбор финального решения:** Подход V23 выбран как наиболее сбалансированный по точности и скорости работы в изолированной среде.
